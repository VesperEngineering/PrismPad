# PrismPad v0.1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish PrismPad v0.1.0 only after Windows and Ubuntu packages pass the complete release gate, while presenting the project with centered artwork and truthful live status badges.

**Architecture:** Keep release identity validation in a small cross-platform Node module, define publication policy as repository tests, and use a dedicated GitHub Actions workflow with platform build jobs feeding one guarded publication job. README presentation and release notes are versioned alongside the workflow so the tag targets one auditable `main` commit.

**Tech Stack:** Node.js 22 project tooling, Node-24-native GitHub Actions, TypeScript 6, Vitest 4, GitHub CLI, Tauri 2, Rust stable, Svelte 5

## Global Constraints

- Version is exactly `0.1.0`; tag is exactly `v0.1.0`; title is exactly `PrismPad v0.1.0`.
- The release is stable, not a prerelease, and targets the exact `main` commit containing the release workflow.
- Published assets are exactly `PrismPad-v0.1.0-windows-x64-portable.exe`, `PrismPad-v0.1.0-windows-x64-setup.exe`, `PrismPad-v0.1.0-linux-x64.AppImage`, and `PrismPad-v0.1.0-ubuntu-24.04-x64.deb`.
- Logs, performance files, unapproved intermediate executables, and CI metadata must not be attached to the public release.
- `package.json`, `src-tauri/Cargo.toml`, and `src-tauri/tauri.conf.json` must all declare `0.1.0`.
- Publication must not run unless both platform jobs and every validation pass.
- An existing `v0.1.0` tag or release is an error; published assets are never overwritten.
- Workflow permissions default to `contents: read`; only the publication job receives `contents: write`.
- Release validation runs for release-affecting pull requests, main-branch pushes, and manual dispatches; publication requires both `github.event_name == 'push'` and `github.ref == 'refs/heads/main'`.
- Node-24-native actions are pinned exactly to checkout `de0fac2e4500dabe0009e67214ff5f5447ce83dd` (`v6.0.2`), setup-node `48b55a011bda9f5d6aeb4c2d9c7362e8dae4041e` (`v6.4.0`), upload-artifact `043fb46d1a93c77aae656e7c1c64a875d1fc6a0a` (`v7.0.1`), and download-artifact `3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c` (`v8.0.1`).
- Setup Node keeps explicit `cache: npm` and sets `package-manager-cache: false`; the approved pinned `dtolnay/rust-toolchain` revision remains unchanged.
- Linux downloads exactly five Tauri AppImage helpers into `$HOME/.cache/tauri`, checks the literal SHA-256 manifest with `sha256sum --check`, and makes them executable before Tauri bundling can use the cache.
- The Linux helper scripts use immutable commit URLs; mutable release URLs are accepted only behind the fixed fail-closed SHA-256 values.
- Before staging, Windows must keep the final production portable executable alive for ten seconds and always terminate it; Linux must keep the final AppImage alive until the expected ten-second `timeout` under `xvfb-run` with `APPIMAGE_EXTRACT_AND_RUN=1`.
- Tag absence is accepted only from `git ls-remote` status 2, and release absence only from a GitHub API HTTP 404; all other probe failures abort publication.
- Each platform validates two source packages, copies them to a flat staging directory under the exact public filenames, and revalidates the staged files before upload.
- v0.1.0 remains unsigned until a Vesper Applied LLC Authenticode certificate is configured; release notes must warn about Windows SmartScreen.
- README artwork and badges are centered; CI and release badges use live GitHub state, while platform badges are informational.
- No decorative static “stable,” license, signing, or security badge may imply a capability that does not exist.
- The approved artwork source is `/workspace/scratch/ae51499cdfbf/generated_images/exec-7dce108a-00d5-4937-9c4b-2b70d209436f.png`.
- Keep dependencies locked and do not add a runtime or development package.

- [ ] **Step 3: Implement the version assertion**

Create `scripts/assert-release-version.mjs`:

```js
import { readFileSync } from 'node:fs';
import { resolve } from 'node:path';
import { pathToFileURL } from 'node:url';

const readJson = (path) => JSON.parse(readFileSync(path, 'utf8'));

export const assertReleaseVersion = (root, expected) => {
  if (!expected) throw new Error('Expected release version is required');

  const packageVersion = readJson(resolve(root, 'package.json')).version;
  const cargoSource = readFileSync(resolve(root, 'src-tauri/Cargo.toml'), 'utf8');
  const cargoVersion = cargoSource.match(/^\s*version\s*=\s*"([^"]+)"\s*$/m)?.[1];
  const tauriVersion = readJson(resolve(root, 'src-tauri/tauri.conf.json')).version;

  const versions = [
    ['package.json', packageVersion],
    ['src-tauri/Cargo.toml', cargoVersion],
    ['src-tauri/tauri.conf.json', tauriVersion]
  ];

  for (const [path, actual] of versions) {
    if (actual !== expected) {
      throw new Error(`${path} version must be ${expected}; received ${actual ?? 'missing'}`);
    }
  }
};

const invokedPath = process.argv[1] ? pathToFileURL(resolve(process.argv[1])).href : '';
if (import.meta.url === invokedPath) {
  try {
    assertReleaseVersion(process.cwd(), process.argv[2]);
    console.log(`Release manifests agree on ${process.argv[2]}`);
  } catch (error) {
    console.error(error instanceof Error ? error.message : error);
    process.exitCode = 1;
  }
}
```

  TAG: v0.1.0

jobs:

    name: ${{ matrix.name }} release package
    runs-on: ${{ matrix.os }}
    timeout-minutes: 60
    strategy:
      fail-fast: false
      matrix:
        include:
          - name: Ubuntu 24.04
            os: ubuntu-24.04
            bundle: deb,appimage
            artifact: prismpad-ubuntu-v0.1.0
          - name: Windows
            os: windows-latest
            bundle: nsis

          package-manager-cache: false
      - uses: dtolnay/rust-toolchain@4cda84d5c5c54efe2404f9d843567869ab1699d4 # stable 2026-07-16
        with:
          components: rustfmt, clippy

      - name: Run frontend tests
        run: npm test
      - name: Check Rust formatting
        run: cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
      - name: Lint locked Rust targets
        run: cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets --all-features -- -D warnings
      - name: Run locked Rust tests
        run: cargo test --locked --manifest-path src-tauri/Cargo.toml --all-features
      - name: Build production frontend
        run: npm run build
      - name: Audit offline boundary
        run: npm run audit:offline

        if: runner.os == 'Linux'
        shell: bash

          set -euo pipefail
          tauri_cache="$HOME/.cache/tauri"
          mkdir -p "$tauri_cache"
          curl_args=(--proto '=https' --tlsv1.2 --fail --location --retry 3)

          curl "${curl_args[@]}" \
            --output "$tauri_cache/AppRun-x86_64" \
            https://github.com/tauri-apps/binary-releases/releases/download/apprun-old/AppRun-x86_64
          curl "${curl_args[@]}" \
            --output "$tauri_cache/linuxdeploy-x86_64.AppImage" \
            https://github.com/tauri-apps/binary-releases/releases/download/linuxdeploy/linuxdeploy-x86_64.AppImage
          curl "${curl_args[@]}" \
            --output "$tauri_cache/linuxdeploy-plugin-gtk.sh" \
